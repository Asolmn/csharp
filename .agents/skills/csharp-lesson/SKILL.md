# C# 配套教程生成

## 输入与学习定位

用户只需提供知识点，如 `$csharp-lesson 泛型`、`$csharp-lesson 委托、lambda、event` 或 `$csharp-lesson async/await`，即可执行生成，无需再次询问学习背景、是否需要示例或是否生成文件。仅在确实没有可识别知识点时询问主题。

默认背景：用户具有一定年限的编程开发工作经验，掌握通用编程基础，希望快速系统掌握 C#。不预设具体年限、已知语言或前后端方向，也不假设用户已熟悉某一种编程范式。Unity 是未来用途背景，本项目仅负责 C# 语言与必要的标准库知识。

- 用中文讲解，代码标识符使用常见英文命名。跳过变量、循环等通用启蒙，重点讲 C# 新语法、行为规则和已有编程经验容易迁移错的地方。
- 保持独立知识讲解的深度，不能把教程退化成 Example.cs 的逐行导读。快速学习靠合理排序与例子，不靠省略核心概念。
- 标出第一遍必学、第二遍深入、必要前置知识。只简要补充真正需要的前置，不擅自扩成完整课程。
- 可以用角色、伤害、背包、状态等纯 C# 逻辑，也可用日常开发中的数据处理或业务场景。按概念清晰度选择，不强制游戏化。
- 不添加 UnityEngine、MonoBehaviour、场景、组件、编辑器步骤或游戏资源；不以未来 Unity 用途为由改项目框架或限制为某个 Unity 版本。
- 不为展示知识而堆叠框架、网络服务、数据库或第三方包。一般使用现有 .NET 控制台和标准库。

## 先识别项目，再做最小集成

读取适用的 AGENTS.md、实际项目文件、Program.cs、Lessons/Check.cs、根 README，以及一个相关现有课题的文件。以磁盘当前内容为准，不能硬编码历史绝对路径、命名空间、目标框架或目录层级。

本项目现有约定是：

```text
Lessons/<Topic>/
  README.md     独立教程
  Example.cs    完整示例
  Exercise.cs   用户补主要逻辑的练习，含验证入口
Program.cs      统一运行入口
Lessons/Check.cs 轻量检查工具
README.md       课程索引与运行说明
```

每个用户指定的独立知识点生成这一套文件。为知识点选择简短有效的英文目录/命名空间和稳定的命令别名；例如泛型可用 Generics/generics，事件可用 Events/events。`async/await` 这样的组合语法可视为一个主题；用户明确分列的知识点保留各自教程，必要时互相链接。

新增课题接入现有 Program.cs 分发和根 README 索引；同步帮助文本与运行命令。复用已有命名空间、检查工具和约定，避免多个顶级入口或重复类型。异步课题采用可等待的入口，按需要最小调整分发；不要用 async void 配 Action 导致程序提前结束或检查遗漏异常。

## README.md：先教知识，再教例子

组织内容时覆盖以下层次，标题和篇幅可按主题调整：

1. **学习目标与阅读路线**：具体能做什么、前置知识、必学与进阶划分。
2. **概念与用途**：是什么、解决什么问题、适用与不适用场景。
3. **语法与核心规则**：解释新出现的关键字、声明结构、编译期约束、运行时行为。用独立短片段展示，不要求读者先看完整示例。
4. **已有知识迁移（按需）**：用户或当前会话明确提供熟悉的语言时，对照其相似点、差异和类比失效的边界；没有直接对应机制时明确说明，不能强行等同。未提供语言背景时，用通用编程概念解释 C#，不默认使用 Go 或其他语言，也不为此打断生成流程。
5. **常见错误与边界**：给出足以复现的短代码、错误原因、正确写法；标清哪些代码故意不能编译，哪些依赖前文声明。
6. **完整示例导读**：链接 Example.cs，提供运行命令、需要观察的现象、关键输出及其对应的语言规则。不能用此节代替前面的理论。
7. **练习任务与验收**：链接 Exercise.cs，说明各 TODO 的输入、输出、规则、异常或失败结果、运行方式，以及预期检查结果。
8. **自测问题**：少量预测行为或解释原因的问题。可提供折叠答案要点，但不泄露练习完整实现。

重点是读者只阅读 README 就能理解该知识点，不是罗列术语或只说“这个方法做了什么”。对正常运行代码和故意错误片段作明确区分；不要让读者将互相独立的代码块误拼成一个程序。版本敏感语法/API 按项目实际 SDK 验证，有必要时查官方资料，不承诺与未来 Unity 工程直接兼容。

## Example.cs：小而完整、可观察

- 提供完整可运行实现和符合当前项目约定的入口；不要残留未实现占位。
- 每个示例围绕当前主题选择少量关键行为，兼顾正常使用和一个重要差异或边界。
- 注释解释“为什么发生这个行为”，已知用户语言背景时可补充有帮助的对照，避免把每行代码翻译成中文。
- 用明确输出展示语义，鼓励先预测再运行；故意抛异常的演示在局部处理，不让完整示例意外中断。
- 示例和练习验证同一组核心知识，但练习在场景或条件上略有变化，避免逐字照抄。避免无关的业务复杂度。
- 时间、随机数、并发和异步主题尽量使用可控输入和同步条件；不要把不确定输出顺序写成固定答案。

## Exercise.cs：能编译的骨架，主要逻辑留给用户

提前提供类型结构、方法签名、必要依赖、输入数据和验证入口。把体现当前知识点的主要逻辑留在 TODO 中；占位方法可抛 NotImplementedException，使新骨架仍能编译，并由运行入口提示未完成。

- 不预填核心实现，不把完整答案隐藏在同一文件、注释或另一个 Solution.cs 中；用户要求答案时再处理。
- TODO 明确方法职责、返回约定、校验规则和状态变化。教程、注释与检查必须一致。
- 检查覆盖正常行为、与本知识点相关的边界、一个能暴露常见误解的场景。例如接口验证传入的新实现确实被调用，struct 验证副本与原值，事件验证取消订阅后不再收到通知。
- 断言可观察行为而非源代码写法；不通过查字符串或文件结构来“验证理解”，不把任意实现细节当唯一解。
- 只读概念可配预测输出、解释题；需要修改签名或类型声明的主题，可让用户填写一个可编译的辅助类型/方法并配人工自检点，不故意交付无法构建的骨架。
- 未完成练习显示未完成，不冒充通过；新检查失败应提供有用原因。不要吞掉所有异常并当作预期成功。

## 重复调用与保护学习进度

先检查主题是否已存在，存在则做针对性更新，不重复创建同义课题或重复注册命令。读取练习内容，保留用户已填写的代码，不用模板覆盖答案，也不为了让构建通过擅自重置用户修改。

已有练习与新教学目标冲突时，保留原练习；可增加清楚命名的进阶练习并单独登记入口。用户只要求改文档或复习时遵循该范围，不自动重建整套文件。非目标课题保持原状。

## 验证与交付

1. 构建项目，确认新示例和未填的新骨架均可编译，不引入新警告。检查若被原有用户代码阻塞，准确报告现状；需要时在临时项目隔离验证新增课题，不能把隔离成功说成整个项目成功。
2. 运行本次新增/修改的示例，对照文档输出；只在入口或共享工具变更时扩大验证到受影响的现有课题。
3. 运行新练习骨架，确认未完成提示和退出行为符合入口约定。骨架未完成不算练习通过。若验证检查可达性确有必要，可在隔离临时副本填参考实现运行，但不改用户练习或将答案放进项目。
4. 检查文档链接、命令别名、代码围栏，以及 README、Example、Exercise 三者的知识点和规则是否一致。
5. 最终给出生成文件的入口链接、可复制的运行命令和实际验证结果，说明主要 TODO 所在位置。不要在对话里重复整篇教材，不把仅生成文件说成已验证用户学会。

调用样例：

```text
$csharp-lesson 泛型
$csharp-lesson 委托、lambda、event
$csharp-lesson async/await
```

这些调用都应真正落地相应文件并完成必要集成，而不是只输出建议、目录规划或一份对话中的教程。
